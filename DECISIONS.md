# Decisions

Format: date · who · decision · why.

- 2026-11-15 · P1 · **Pydantic is the source of truth for contracts.** `contracts/schemas/*.json` are generated by `python contracts/gen_schemas.py`; a test fails if they drift. Pydantic emits JSON Schema **2020-12**, not Draft 7 as §4.1 says. The difference doesn't matter for our shapes (no `$defs`-vs-`definitions` consumers yet). Tell P1 if the TS side needs strict Draft 7.
- 2026-11-15 · P1 · **`VerifyRequest.approve_big_rewrite: bool = false`** added. §3 says "BLOCK if big_rewrite **unapproved**", so the approval needs a field. The extension sets it after a human approves a large rewrite and re-submits.
- 2026-11-15 · P1 · **`Verdict.decision_reason`** (string) added so BLOCK always carries a plain-English reason (DocSync lesson: make failures loud).
- 2026-11-15 · P1 · **Sandbox default = local temp dir**, with Docker (`--network none`) opt-in via `PCP_SANDBOX=docker`. The local sandbox only denies network on a best-effort basis (proxy vars cleared); real isolation needs Docker.
- 2026-11-15 · P1 · **Baseline run = original source + the patch's test-file hunks.** That's the only way new F2P tests can actually *fail* on old code.
- 2026-11-15 · P1 · **LLM providers are pluggable** (OpenAI-compatible HTTP + a scriptable `fake` provider). Real models to be chosen once the TrueForge docs are confirmed.
- 2026-11-16 · P1 · **Proof-checker modifiers:** regression (existing passing test now fails) **100, warning** (not critical), so a broken edge case goes to the REPAIR loop with the test output instead of straight to a human. Critical is reserved for tampering (95) and safety/scope criticals. New tests still failing → 90 (forces REPAIR: 100 − 90×0.35 = 68.5); tests that already pass on old code → 60; source change without F2P → 40 (REVIEW, but `unproven`).
- 2026-11-16 · P1 · **Every attempt's diff is relative to the user's original repo** (nothing reaches disk before a hunk is accepted). `attempt` must be `previous.attempt + 1`, with `previous_patch_id`; the server returns 422/404 otherwise.
- 2026-11-16 · P1 · **LLM findings carry zero risk until the validator confirms them**; then risk = `round(60 × confidence)`, merged with `max()`. An LLM can raise a warning but never a critical.
- 2026-11-16 · P1 · **Tamper protection covers** pre-existing tests in touched test files plus the frozen F2P tests: deleted, skip/xfail added (decorator, `pytest.skip()`, module `pytestmark`, or runtime skip), fewer real asserts (`assert True` doesn't count), or fewer literal parametrize cases. A test renamed with an identical body is reported as `renamed` (warning).
- 2026-11-16 · P1 · **Test scope = whole suite** by default (`PCP_TEST_SCOPE=related` narrows it). Flask's suite takes ~6 s; catching regressions anywhere is worth it.
- 2026-11-16 · P1 · **Hard-coded-password rule skips test files** (fixtures like `SECRET_KEY="dev"`) and masked placeholders (`'********'`). Real key formats (AKIA, ghp_, sk-, PEM) are still flagged everywhere.
- 2026-11-16 · P1 · **Server security:** browser `Origin` headers other than VS Code webviews/localhost get 403 (CSRF: `/verify` executes code); optional `PCP_API_TOKEN` → `X-PCP-Token` header.
- 2026-11-16 · P1 · **Flask bench venv pins pytest 8.4.2** from Flask's `uv.lock`: Flask 3.1.3's tests import `_pytest.monkeypatch.notset`, which pytest 9 removed. `tests/test_reqctx.py::test_bad_environ_raises_bad_request` fails on unpatched 3.1.3 in this env; the proof runner treats it as pre-existing, not as a regression.
- 2026-11-16 · P1 · **Docker sandbox verified** (`PCP_SANDBOX=docker`, image from `verifier/docker/Dockerfile.sandbox`): `--network none`, 2 GB / 2 CPU / 512 pids, non-root user. The whole shadow folder is mounted at `/sandbox`. A timeout or cancel `docker kill`s the container, not just the CLI. Same decisions as the local sandbox on tiny_repo (9/9) and Flask A/B. On Windows it is ~4x slower on Flask (~40 s vs ~11 s per verification) because of bind-mount I/O, so **local stays the default**; use Docker when untrusted patches need real network isolation (or on Linux, where mounts are fast).
